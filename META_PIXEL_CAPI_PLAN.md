# Implementation Plan: Meta Pixel & Conversions API (CAPI)

This document outlines a complete, step-by-step strategy for properly integrating the Meta Pixel and Conversions API into your Next.js 14 (App Router) e-commerce application. 

## 1. Prerequisites and Setup Requirements
Before writing any code, gather the following credentials from your Meta Business Manager:
- **Meta Pixel ID**: Found in Events Manager > Data Sources.
- **Conversions API Access Token**: Found in Events Manager > Settings > Generate Access Token.
- **Test Event Code**: Needed temporarily for testing server events (e.g., `TEST12345`).

Add these to your local `.env.local` and production environment variables:
```env
NEXT_PUBLIC_META_PIXEL_ID=your_pixel_id
META_CAPI_ACCESS_TOKEN=your_capi_access_token
META_CAPI_TEST_CODE=your_test_code # Remove in production
```

## 2. Phase 1: Client-Side Meta Pixel Integration
We will integrate the base pixel script and client-side event tracking.

### Step 2.1: Base Pixel Component
Create a `src/components/MetaPixel.tsx` component using `next/script`.
- This script will initialize `fbq` (Facebook Pixel) on the client side.
- It should automatically trigger a `PageView` event on route changes by listening to `usePathname` and `useSearchParams` from `next/navigation`.

### Step 2.2: Add to Root Layout
Import and include the `<MetaPixel />` component inside the `<body>` of your `src/app/layout.tsx` so it is active across all pages.

### Step 2.3: Client Event Utility
Create a utility function (e.g., `src/utils/meta-pixel.ts`) with a function `trackPixelEvent(eventName, data, eventId)` to safely call `window.fbq` anywhere in the app without throwing errors if the script hasn't loaded yet.

## 3. Phase 2: Server-Side CAPI Integration
The Conversions API sends data directly from your server to Meta, bypassing browser ad-blockers, tracking prevention (ITP), and privacy restrictions (like iOS 14.5+).

### Step 3.1: Server-Side Utility
Create a utility file `src/lib/capi.ts` containing a function `sendCAPIEvent()`.
- Use native `fetch()` to POST data to the Meta Graph API: `https://graph.facebook.com/v19.0/${PIXEL_ID}/events`.
- Construct the payload according to Meta's strict requirements: an array containing `event_name`, `event_time`, `user_data` (IP address, user agent, `fbp`, `fbc` cookies, and optionally hashed emails/phone numbers), `custom_data` (value, currency, contents), and `event_id` (CRITICAL for deduplication).

### Step 3.2: Internal API Route for CAPI
Since the client doesn't have the secure CAPI Token, we will create an internal Next.js Route Handler (`src/app/api/tracking/meta/route.ts`).
- This route receives event details from the frontend, automatically captures server-side data like IP address (`req.headers.get('x-forwarded-for')`) and User-Agent, reads the `_fbp` and `_fbc` cookies generated by the Pixel, hashes user details (if provided), and forwards the request to Meta via `sendCAPIEvent()`.

## 4. Phase 3: Event Tracking & Deduplication (Crucial Step)
When sending both Pixel (browser) and CAPI (server) events, Meta will count them twice unless we deduplicate them. Deduplication requires sending the **exact same `event_name`** and **`event_id`** from both the client and the server.

### Standard E-commerce Events to Implement:
1. **ViewContent**: Triggered when a user views a specific product page.
2. **AddToCart**: Triggered when a user clicks to add an item to the cart.
3. **InitiateCheckout**: Triggered when a user begins the checkout process.
4. **Purchase**: Triggered after successful payment confirmation.

### Implementation Flow per Event (Example: Add to Cart):
1. User clicks "Add to Cart".
2. Generate a unique ID for this specific action, e.g., `const eventId = crypto.randomUUID();`
3. **Client Side**: Call your Pixel utility: `trackPixelEvent('AddToCart', { content_ids: ['PROD-1'], value: 599, currency: 'INR' }, eventId)`.
4. **Server Side**: Make a `POST` fetch to your internal API (`/api/tracking/meta`) with the identical event details and `eventId`. The API route processes it and forwards it to Meta via CAPI.

## 5. Phase 4: Testing & Validation
Testing is essential to ensure events are tracked and deduplicated properly.
1. **Client Events**: Install the "Meta Pixel Helper" Chrome extension. Navigate your site and verify standard events and `PageView` fire correctly without errors.
2. **Server Events & Deduplication**: Go to Meta Events Manager -> Data Sources -> Select your Pixel -> "Test Events" tab.
   - Enter your server's test code in `.env.local` (`META_CAPI_TEST_CODE`).
   - Perform actions on your local or staging site.
   - Verify that the Events Manager dashboard shows both "Browser" and "Server" versions of the event.
   - Ensure the event shows a green **"Deduplicated"** badge in the Test Events tool.

## 6. Phase 5: Advanced Matching (Optional but Recommended)
To maximize ad attribution and performance, collect and pass 1st-party user data when available (especially for `InitiateCheckout` and `Purchase`):
- **Server-Side**: Hash user email, phone number, first name, last name, city, and state using SHA-256 before sending them in the `user_data` payload via CAPI.
- **Client-Side**: Pass unhashed data to the Pixel (e.g., `fbq('init', PIXEL_ID, { em: 'user@email.com' })`) if they are logged in, as the Meta Pixel automatically hashes it before sending.
